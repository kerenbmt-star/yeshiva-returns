# מערכת ניהול החזרות הוראות קבע – ישיבת סלונים

מערכת Web נפרדת שמטפלת רק בחיובים שחזרו, ולא מחליפה את תוכנת הוראות הקבע הקיימת. אפשר לקלוט קובץ החזרות חודשי, לאחד את החיובים לתיק אחד לכל איש קשר, לשייך תיקים לעובדים, לתעד שיחות ולעקוב אחרי כל תיק עד שהוא נסגר.

## ארכיטקטורה (פשוטה ויציבה)

| רכיב | טכנולוגיה |
|---|---|
| שרת | Node.js + Express (קובץ `server.js`) |
| מסד נתונים | SQLite – קובץ אחד `data/returns.db` (נשמר קבוע, גם אחרי סגירת הדפדפן) |
| ממשק | HTML/CSS/JavaScript, עברית מלאה ו-RTL, ללא בנייה (build) |
| Excel | ExcelJS – קליטה וייצוא |
| מייל | Nodemailer (SMTP) – פעיל רק לאחר הגדרה ובדיקה |

### מבנה הנתונים – הפרדה בין האדם לאירועי החיוב
- `contacts` – פרטי האדם (מזהה איש קשר ייחודי, שם, טלפונים, כתובת).
- `return_events` – כל חיוב שחזר (תאריך, סכום, סיבה, קוד, אסמכתא, השורה המקורית מהקובץ).
- `cases` – תיק טיפול (סטטוס, מטפל, תאריך מעקב). לכל אדם יש תיק פתוח אחד לכל היותר. חיובים חדשים מצטרפים לתיק הפתוח, ואם התיק הקודם נסגר נפתח תיק חדש. התיקים הקודמים מוצגים בכרטיס.
- `actions` – היסטוריית פעולות ותיעוד שיחות. `assignments` – היסטוריית שיוכים.
- `imports` – יומן ייבוא. `notifications`, `email_outbox`, `call_queue` – תזכורות ואוטומציות.

## התקנה והרצה

דרוש Node.js בגרסה 18 ומעלה (מומלץ 22).

```bash
npm install
```

```bash
npm start
```

אחר כך פותחים בדפדפן את `http://localhost:3000`. בכניסה הראשונה יוצרים חשבון מנהל.

משתני סביבה אופציונליים:
- `PORT` – פורט (ברירת מחדל: 3000).
- `DATA_DIR` – תיקיית הנתונים (ברירת מחדל: `./data`).
- `SECURE_COOKIE=1` – חובה כשהמערכת רצה מאחורי HTTPS.

### הפעלה לכמה עובדים (שרת)
כדי שכמה עובדים יעבדו במקביל, המערכת צריכה לרוץ על מחשב או שרת אחד שכולם ניגשים אליו:
- **ברשת המשרד**: מריצים על מחשב קבוע במשרד, והעובדים נכנסים לכתובת `http://<כתובת-המחשב>:3000`.
- **בענן**: שרת VPS קטן (למשל DigitalOcean, Hetzner או Linode) עם HTTPS (Caddy או Nginx), או שירות כמו Render או Railway **עם דיסק קבוע** שמחובר לתיקיית `data`. בלי דיסק קבוע הנתונים יימחקו.
- בענן חובה להפעיל HTTPS ולהגדיר `SECURE_COOKIE=1`.

## הרשאות
- **מנהל**: ייבוא קבצים, ניהול עובדים, הגדרות, גיבוי, וגם כל מה שמטפל יכול.
- **מטפל**: צפייה בכל התיקים, תיעוד פעולות, שינוי סטטוס, שיוך והעברה של תיקים, ייצוא ל-Excel.
- אפשר להוסיף עובד גם בלי שם משתמש וסיסמה. במקרה כזה אפשר לשייך אליו תיקים, אבל הוא לא יכול להיכנס למערכת. **ירון רוטנברג** כבר מוגדר במערכת כמטפל. כדי לאפשר לו כניסה, מגדירים לו שם משתמש וסיסמה במסך "עובדים".
- הסיסמאות נשמרות מוצפנות (scrypt). יש הגבלה על ניסיונות כניסה כושלים, והסשן נשמר בעוגייה מסוג HttpOnly.

## ייבוא חודשי
1. במסך "ייבוא קובץ" בוחרים קובץ `.xlsx` או `.csv`. קובץ `.xls` ישן צריך קודם לשמור ב-Excel בשם כ-`.xlsx`.
2. המערכת מוצאת את שורת הכותרות ומזהה את העמודות לפי השמות שלהן, למשל "מזהה איש קשר", "שם", "טלפון", "סכום", "סיבת החזרה". אם משהו זוהה לא נכון, מתקנים את המיפוי ידנית ובודקים בתצוגה המקדימה.
3. אחרי הקליטה מוצג סיכום: כמה שורות נקלטו, כמה תיקים חדשים נוצרו, כמה תיקים קיימים עודכנו, כמה כפילויות זוהו, כמה שורות היו שגויות, ומה הסכום הכולל.

**מניעת כפילויות**: לכל חיוב נוצרת "טביעת אצבע" לפי מזהה איש קשר, תאריך, סכום, סיבה, קוד, אסמכתא וחשבון. כשמייבאים שוב את אותו קובץ (או קובץ שחופף לקודם), חיובים שכבר קיימים מדולגים. שני חיובים זהים באמת באותו קובץ לא נבלעים זה בזה.

שורת סיכום בתחתית הקובץ ("סה"כ") מזוהה ומדולגת. שורה בלי מזהה איש קשר לא נקלטת ומופיעה ברשימת השגיאות.

## סטטוסים
חדש → בטיפול → ממתין לחודש הבא / טופל / לא ניתן לטיפול.
- **ממתין לחודש הבא**: חובה לקבוע תאריך מעקב עתידי. בתאריך הזה התיק חוזר אוטומטית לסטטוס "בטיפול", ונשלחת תזכורת למטפל.
- **טופל**: אפשר לבחור רק אחרי סימון "אני מאשר/ת שהחוב הוסדר" ופירוט איך הוסדר. השרת אוכף את זה.
- **לא ניתן לטיפול**: חובה לכתוב את הסיבה.
- תיעוד הפעולה הראשונה בתיק "חדש" מעביר אותו אוטומטית ל"בטיפול".

## תזכורות ואוטומציות – מה פעיל ומה דורש חיבור
| יכולת | מצב |
|---|---|
| תזכורת על תיק שלא טופל X ימים (ברירת מחדל: 7) | **פעיל** (תזכורת פנימית בפעמון) |
| תזכורת במועד המעקב והחזרת תיקים ממתינים לרשימה הפעילה | **פעיל** |
| הכנת הודעות מייל לעובדים (תיבת יוצא) | **פעיל** – נשמרות כטיוטות |
| שליחת מייל בפועל | **דורש חיבור SMTP** במסך הגדרות. נדלק רק אחרי שמייל בדיקה נשלח בהצלחה |
| שיחה אוטומטית עם הודעה מוקלטת | **דורש ספק חיוג** (Twilio, ימות המשיח, Call2All וכד'): כתובת API, מפתח API ומספר יוצא. עד שמתחברים, הבקשות נשמרות בתור ולא מתבצעת שום שיחה |

הבדיקה האוטומטית רצה כל 30 דקות. במסך "תזכורות ואוטומציות" אפשר גם להריץ אותה ידנית.

**על חיוג אוטומטי**: לכל ספק יש API שונה. המתאם שנמצא ב-`src/integrations.js` (הפונקציה `processCallQueue`) שולח בקשת POST בפורמט JSON: `{to, from, message, reference}`. אחרי שבוחרים ספק צריך להתאים את הפונקציה לפי התיעוד שלו. אם זה ספק ישראלי, מומלץ לבדוק מולו את דרישות החוק לגבי שיחות יזומות.

**חיבור Gmail**: שרת `smtp.gmail.com`, פורט 587, STARTTLS. שם המשתמש הוא כתובת ה-Gmail, והסיסמה היא "סיסמת אפליקציה" שיוצרים בחשבון Google (דורש אימות דו-שלבי).

## גיבוי וייצוא
- גיבוי אוטומטי יומי של מסד הנתונים נשמר ב-`data/backups`. נשמרים 30 הגיבויים האחרונים.
- במסך הגדרות אפשר להוריד גיבוי מלא של מסד הנתונים.
- כפתור "ייצוא ל-Excel" מוריד קובץ עם הגיליונות: תיקים, חיובים שחזרו, היסטוריית פעולות, אנשי קשר, היסטוריית שיוכים.
- **חשוב**: לגבות את תיקיית `data` למקום חיצוני (דיסק או ענן) באופן קבוע.

### שחזור מגיבוי
עוצרים את השרת, מחליפים את `data/returns.db` בקובץ הגיבוי ומפעילים מחדש.
